# Фенотипы органелл: самообученные представления против ручных признаков

Код магистерской работы «Методы глубокого обучения для выявления и классификации клеточных фенотипов по изображениям органелл» (МФТИ, 2026–2027). Автор: Рыжков В. Н., научный руководитель: Крицкая К. А. (ИБК РАН).

**Задача.** По конфокальным снимкам живых первичных фибробластов уха *Acomys* и *Mus musculus* (молодые и старые животные, рентгеновское облучение 0, 5 и 10 Гр, съемка через 48 ч; каналы MitoTracker Green, LysoTracker Red, Hoechst) отличить облученные клетки от контрольных и сравнить три способа описания клетки:
- **A** — традиционные признаки после сегментации: морфология и граф митохондриальной сети, лизосомы, форма и текстура ядра, ассоциация лизосом с митохондриями;
- **B** — самообученная модель DINOv2 без дообучения + линейный классификатор;
- **C** — ResNet-50, обученная с учителем на ImageNet (замороженная и дообученная);
- **D** — гибриды A и B (склейка признаков, стекинг, простое усреднение).

**Гипотезы:**
- **H1:** B точнее A не менее чем на 10 п. п. сбалансированной точности.
- **H2:** в представлении B есть информация об облучении, которую A не объясняет (остаток дает не менее 10 п. п. над случайным уровнем).
- **H3:** ответ на облучение у *Acomys* не более половины ответа у *Mus* (R ≤ 0,5).

Валидация во всех случаях — исключение целой культуры (животного), 12 блоков. Подробное обоснование — в тексте ВКР.

## Данные

Снимки (123 TIFF, 3 канала, 68 МБ) в репозитории не хранятся. Они лежат на Google Диске в папке исследования:
`I — НИР 3/02 — Артефакты исследования/01 Данные/data.zip`.
Доступ — по ссылке от автора.

## Запуск

1. Открыть [`notebooks/VKR_colab.ipynb`](notebooks/VKR_colab.ipynb) в Google Colab: Файл → Открыть блокнот → GitHub → адрес этого репозитория.
2. Среда выполнения → **A100** (или T4).
3. Указать источник данных в ячейке данных. Есть три варианта:
   - ссылка на `data.zip` с доступом «Все, у кого есть ссылка» (`DATA_GDRIVE_URL`);
   - подключение своего Google Диска, на котором есть папка исследования или ярлык на нее;
   - перетащить `data.zip` в панель «Файлы».
4. Запустить ячейку установки (сеанс перезапустится), затем «Выполнить все ниже». На A100 около 40–60 минут. Результаты — архив `results.zip`.

Вне Colab ноутбук выполняется так же, например через `papermill`. Перезапуск сеанса и скачивание архива при этом пропускаются, рабочая папка задается переменной `VKR_WORKDIR`, ссылка на данные — `VKR_DATA_URL`.

## Что считает ноутбук

| Раздел | Содержание | Основные результаты |
|---|---|---|
| 1. Контроль качества | каналы по LUT, размер пикселя, насыщение, резкость | `qc_table.csv` |
| 2. Сегментация | ядра Cellpose (основной вариант) и классические; территория центральной клетки; митохондрии, лизосомы; согласие методов; выгрузка снимков для ручной разметки | `masks/`, `seg_agreement.csv` |
| 3. Признаки | признаки A по обоим вариантам сегментации, критерии исключения | `features.csv`, `features_classic.csv` |
| 4. Представления | DINOv2 ViT-S/14 и ViT-B/14, ResNet-50 | `emb_*.npz` |
| 5. Дообучение ResNet-50 | 12 блоков LOCO | `oof_resnet_ft.csv` |
| 6. Сравнение и гипотезы | модели A–D, H1–H3 с поправкой Холма, анализы чувствительности, влияние сегментации, батч-эффект, кластеры, кривые обучения | `results_models.csv`, `hypotheses.csv`, `h3_sensitivity.csv`, `validation_sensitivity.csv`, `segmentation_impact.csv` |

**Ручная разметка.** Сейчас основная сегментация ядер выполняется моделью Cellpose без дообучения, чтобы был стартовый результат. Ручная разметка 18 снимков будет сделана позже. По ней посчитаются Dice, IoU и F1, и проверится, меняется ли классификация при замене автоматических масок ручными. Если разность сбалансированной точности меньше 5 п. п. и ее 95% ДИ включает ноль, полная ручная разметка не нужна.

## Структура

```
notebooks/VKR_colab.ipynb   ноутбук (собирается автоматически, руками не править)
src/vkr_lib.py              функции: чтение, сегментация, признаки, статистика
tools/make_colab.py         описание всех ячеек ноутбука; встраивает src/vkr_lib.py
tests/                      проверки на синтетических изображениях
.github/workflows/ci.yml    проверки при каждом пуше в main
```

## Разработка

```bash
python tools/make_colab.py            # пересобрать ноутбук после правок в src/ или tools/
pip install -r requirements-ci.txt
pytest -q tests                       # быстрые тесты, без данных и GPU
```

CI при каждом пуше в `main` проверяет две вещи: что закоммиченный ноутбук собран из актуальных исходников и что тесты проходят. Полный анализ запускается вручную в Google Colab. Последняя ячейка скачивает `results.zip`, а архив результатов и выполненный ноутбук кладутся в папку исследования на Google Диске (`02 — Артефакты исследования/03 Результаты экспериментов`), не в репозиторий.
